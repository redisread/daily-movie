# 随机漫步与内容修正 · 2026-11-07

## 实现合同

- 不新增随机API：完整读取无鉴权 `GET /api/v1/movies?limit=100` 的全部页，只取公开可浏览条目；分页失败、重复/循环或超过1000部明确失败，不偷换成最近12部。
- Fisher–Yates 洗牌袋，不放回；袋空后显示“再走一轮”，不与上一轮末尾连重。回看保存实际ID；回看后的下一步先重放既有路径。
- `daily-movie:walk:v1` sessionStorage 保存ID、袋、去重集合及游标，路径最多100条，计数不受历史截断影响；损坏状态复位。存储失败退为App内存，详情返回仍可继续，刷新可能重置。
- `?movie=id` 选择影片，`mode=walk` 恢复玩法；无会话的新标签以该影片为新起点，不复制别人的历史。
- 普通箭头、海报点击退出漫步，结束按钮不改变影片。最多12张稳定日期/id排序窗口；抽到窗口外影片时换掉最旧预览。
- 键盘/reduced-motion即时切换，鼠标沿用420ms；准备期间保留按钮焦点，以aria-disabled和事件保护阻止再抽。序号+AbortController防止旧响应提交，成功后才消耗袋。失败可重试，404候选从范围移除。
- 0部空态；1部静态提示；历史/图集均不伪造。公开影片逐次重新读取，所有前端请求无写密钥。

## 只读计划与经审写入

```sh
npm run content:plan
# artifacts/content-correction-plan.json / content-correction-diff.md
```

默认读取当前公开D1 API，不使用旧Markdown导入文件作生产真相。`--input <公开API快照.json>` 只用于复现已留存的对照。JSON包含逐片原字段、目标PATCH、原ETag、稳定幂等键、原金句指纹与仅变更字段的回滚载荷；Markdown用于人工核对。

**提交PR不等于已修改线上数据。** 生产写入需按当次计划另行确认执行人和授权；旧上线许可不能复用。默认生产配置为真实D1，勿运行远端导入或全库重置来修正内容。

经审且已有当前授权的密钥持有人，在安全环境提供 `CONTENT_API_KEY` 后执行（不把值贴到聊天或命令记录）：

```sh
npm run content:apply -- artifacts/content-correction-plan.json --apply
```

执行器仅允许目标生产origin；读写均显式请求 `Accept-Encoding: identity`，避免压缩代理将版本标签弱化。预读必须得到与响应版本一致的强ETag；弱/缺失标签直接停止，绝不剥掉 `W/` 当作并发凭据。先预读全部目标，任何版本/金句冲突在新写入前停止。只允许 `posters/whyThisMovie/synopsis`，绝不携带quotes、cast、cover或其他整库字段。每片使用原If-Match和稳定Idempotency-Key；中途412/429/网络结果不明立即停，回执写 `artifacts/content-correction-receipts.json`，无密钥。

网络超时不等于未写入；保留原计划和原键进行服务器幂等重放，不能盲目换键。重放也要求当前读取具有强ETag，且仍发送原If-Match/原键；由服务器原回执确认，不能把目标字段相同当作已获新写入许可。如果已接受的写响应仍缺少强ETag，保存“待验证”回执后停止后续条目，不能强行继续。若已有其他编辑/新增金句，重新读取并人工审阅新对照；不得将数据库压回“12/37”——生产还有应保留的QA草稿及审计数据。

## 回滚

1. 查回执和当前GET，确认目标字段仍为本次修改，且没有需要保留的后续编辑。
2. 只用对应条目的 `rollback` 字段PATCH，配当前ETag与独立稳定回滚键；冲突先审，不强制覆盖。
3. 不恢复全库备份、不删除QA记录、不发送quotes；新增金句保持不变。
4. 代码回滚另走PR/部署流程；main合并会触发Cloudflare自动部署，不能把合并视为无副作用的整理。
